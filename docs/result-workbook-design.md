# Result workbook restoration design

Status: implemented as a separate result-workbook restoration path for related
sheet bundles. Existing editable-workbook and append-results modes retain their
current contracts. The current result path accepts static short result values;
formula results, arbitrary free text and novel UUID-shaped codes remain blocked.

## Intended workflow

1. The operator protects selected source worksheets as today. The protected copy
   supplies random `entity_id` values for participants, random `record_id` values
   for source rows and only the source fields approved for analysis.
2. The operator works with ChatGPT on the analysis rules. A short SafeSet prompt
   explains the output contract; an optional task description may use the exported
   worksheet and field names. The rules need not be fixed at protection time.
3. ChatGPT returns a new `.xlsx` workbook containing the result worksheets it
   created. It may add, remove or rename result sheets, fields and rows. It need
   not copy any original protected worksheet. Participant-level rows carry a
   known `entity_id`; `record_id` is included only when a result refers to one
   particular source row. Summary rows do not claim a participant identity.
4. SafeSet reads the returned workbook, exact original and private bundle locally.
   The operator selects which original source fields to join to each participant
   result sheet. SafeSet validates and reviews the joins and result values, then
   creates a new sensitive workbook containing only the result sheets.

The original workbook supplies authenticated identities and selected source
attributes. It does not define the result workbook's sheet or row layout.

## Result and identity contract

- Every `entity_id` used in a participant result row must occur in the bundle.
  Unknown or malformed IDs fail. If a `record_id` is provided, it must also be
  known and bound to that row's `entity_id`. Neither ID is guessed or generated by
  the analysis tool.
- A result sheet declares whether it has one row per entity, multiple rows per
  entity or no participant links. A one-row-per-entity declaration makes duplicate
  IDs a validation failure. Result rows are not required to cover every source
  participant; adding and removing result rows does not imply changes to the
  original source.
- Each restored source field is selected explicitly by source worksheet and
  column. The operator chooses an entity or exact-record join for each linked
  result sheet. An entity join requires exactly one matching source row for every
  result row; row-specific joins require a valid `record_id` from the selected
  source sheet. Missing or ambiguous matches block publication. Source fields are
  never copied wholesale by default.
- `entity_id` and `record_id` are control columns. They are removed from the
  locally restored output once selected source identifiers have been joined.
  An unlinked summary sheet contains only reviewed result fields.
- Known obfuscation codes can be decoded only through their authenticated
  field/codebook association. A new result category, such as a newly created
  `Team`, is reviewed as a new output value; it is not inserted into an existing
  source codebook or mistaken for an identity. An unknown UUID-shaped code or an
  ambiguous field/codebook association blocks publication. The review counts
  distinct new category values per result field and requires their approval.

## Validation and approval

The returned workbook is untrusted. SafeSet enforces bounded rectangular tables,
unique headings, supported cell types, no hidden sheets or formula results, safe
result text and explicit result-sheet approval. It validates IDs and joins before
showing a review containing sheet and row counts, output headings, selected source
fields, duplicate/missing-link counts and new category counts. New result
categories and source-field joins require explicit approval. After approval,
SafeSet rereads both workbooks, rechecks the bundle binding and the reviewed
proposal, and publishes to a new local path without overwriting either input.

These checks establish structural and identity integrity. They cannot establish
that ChatGPT followed an allocation rule, that a new team is necessary or that
the result is suitable for a recipient. The operator reviews those decisions.
No source rows, decrypted mapping, passphrase or returned cell values enter
protocol responses or logs.

## Initial use cases

- **Create teams:** ChatGPT returns a new `Allocations` result sheet with one row
  per `entity_id`, plus `Team`, `Role` and other approved result fields. The local
  join adds only the selected original identity and context fields.
- **Update teams:** ChatGPT uses an updated protected classlist to create a new
  allocation result. It may retain existing teams and add result-only team labels
  when needed. It can omit departed participants from the result. The original
  `Allocations` worksheet need not appear in the returned or restored workbook.

No instructions worksheet is required. The task can evolve in ChatGPT; the
protected workbook carries the data and pseudonymous join keys, while SafeSet's
local restoration enforces the output contract.
